# Getting started

> A skeleton. Replace this page with the project's own first steps, written for someone who is not a developer.

A good first page answers four questions, in this order:

1. **What is this for?** One sentence.
2. **How do I start?** The shortest path from nothing to the first useful result, step by step, with the exact words of the buttons and menus.
3. **Where is my work kept, and how is it protected?** Where files go, when they are saved, how to get something back.
4. **What if something goes wrong?** The messages a person might see, and what to do.

Write tasks ("How do I export a PDF?"), not internals. Keep menu names exactly as they are in the program. Add one page per area of the program under `docs/user-guide/` and list it in [the index](../index.md).
